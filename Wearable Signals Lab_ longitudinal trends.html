Wearable signals, read as trajectories

A student research dashboard for exploring daily heart rate, HRV, sleep, activity and skin temperature records. It is a first step into FAIR Labs' digital-biomarker programme: look at how a person changes over time, not at single readings.

Wellness indicators, not diagnosis. These signals describe how one body drifts from its own usual pattern. A flagged day means "different from this person's recent baseline", never "ill" or "healthy". Only a clinician can diagnose. Demo data is synthetic. Records from real people need consent and ethics approval first.

Data

Load a CSV of daily records for one person or many. The file is read inside your browser and is never uploaded.

What the file should contain
ColumnNeededNotes
dateRequiredOne row per person per day, written YYYY-MM-DD
person_idOptionalAn anonymous code such as P01, never a name or email. Leave out for one person
Signal columnsAt least oneAny numeric columns, for example resting_hr, hrv_ms, sleep_hours, steps, skin_temp_dev. Blank cells count as missing
Reference labelOptionalA 0/1 column such as self_reported_unwell. It lets the dashboard report precision and recall
  • Each person needs at least 14 days of data, and 60 or more days works much better.
  • Missing days are fine. They are left as gaps and never filled in.
  • If your device exports hourly or per-minute rows, aggregate to one row per day first. Rows sharing a date are averaged.
  • Use consistent units for each column across all people.

1. Trends and anomaly detection

Each day is compared with the median of the previous days. Shaded days are flagged when enough signals move far from that personal baseline.

2. Correlations between signals

Rows are signal A today; columns are signal B after the chosen lag. Select a cell to see the scatter plot.

Try switching between raw values and deviations. Slow trends (for example gradual fitness gains) can create correlations that vanish once each day is compared with its own baseline. Daily data from one person is autocorrelated, so treat r as a description, not a test result.

3. What this can and cannot say

Reasonable claims
  • Several signals moved together away from this person’s own recent baseline.
  • A lagged correlation was present in this sample.
  • One-signal flags are often sensor or context artefacts.
Not supportable
  • "This person had an infection." No clinical test supports that.
  • "Low HRV causes high heart rate." Correlation says nothing about cause.
  • Any conclusion about other people from one person's data.
Files are processed locally in your browser. The demo data comes from a seeded generator with a planted 6-day episode, a sensor glitch and a very short night.
